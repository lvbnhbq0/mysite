**Version control** is a way to keep a history of file changes and return to earlier states of a project when needed. It makes teamwork easier and reduces the fear of “breaking” your working copy—you can always roll back or see exactly what changed.

**Git** is the most widely used version control system. You save snapshots (**commits**), use **branches** for parallel work, and sync your code with a remote repository (for example on **GitHub**).

For students, this pays off in labs, coursework, and side projects: a clear change history, an off-site backup, and early practice with how software teams actually work.
